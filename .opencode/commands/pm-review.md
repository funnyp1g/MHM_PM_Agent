# PRD 评审

请从资深产品经理视角，评审以下 PRD / 需求方案。

## 评审对象

$ARGUMENTS

## 执行要求

1. 先读取 `pm-agent-core/README.md`、`ROLE.md`、`KNOWLEDGE.md`、`BOUNDARIES.md` 和 `REVIEW.md`，再加载 `product-knowledge` 技能读取产品知识库，交叉核对评审对象；涉及字段、金额、数量、库存、状态或指标时，同时读取 `data-dictionary.md`、`metrics.md` 和 `open-questions.md`。
2. 加载 `prd-writing` 技能，以模板要求为基准逐项检查。
3. 加载 `requirement-analysis` 技能，检查需求拆解与关联分析是否完整。
4. 如果评审过程中发现名词含义、业务逻辑或交互样式存在不确定、歧义或多个合理解释，先暂停评审并向用户提问；得到回答后再继续评审，不得自行补充结论。

## 评审维度

- **完整性**：背景/目标/非目标/用户场景/功能需求/验收标准是否齐全
- **可落地性**：业务规则是否明确、验收标准是否可判定（Given/When/Then）
- **关联一致性**：术语是否与 `glossary.md` 一致；功能关联是否与 `relations.md` 一致
- **原型一致性**：涉及页面时，Open Design 原型是否有可追溯链接/标识；页面ID映射是否清楚；页面、字段、状态和跳转是否与 PRD 一致
- **设计落地性**：原型是否遵循 `ui/design-system.md` 和现有页面范式；是否覆盖默认、空态、加载、错误、禁用及关键成功/失败反馈
- **范围控制**：目标/非目标是否清晰，是否过度承诺
- **遗漏与风险**：边界、异常、权限、数据、依赖是否有遗漏
- **证据与口径**：字段、金额、数量、库存、状态和指标是否有来源；假设是否明确；P0/P1 待确认项是否同步
- **完成状态**：评审状态是否与实际完成程度一致；未完成原型不应被描述为已确认事实

## 输出格式

- **总体评价**：（一句话结论）
- **问题清单**（按严重度排序：阻塞/重要/建议）
  - 位置 + 问题 + 修改建议
- **修改优先级建议**

评审结束前运行 `.opencode/scripts/validate-pm-agent.mjs <PRD路径>`，把校验失败项列入问题清单。

涉及页面且用户已选择制作原型的 PRD，额外输出以下检查结果：

- Open Design 原型链接/标识及评审状态
- PRD 页面ID与原型页面的映射
- 原型与 PRD 的字段、规则、状态、跳转差异
- 已回写 `product-knowledge/ui/` 的页面与导航关系，或未回写的原因

涉及页面但用户未选择原型时，明确记录“未制作原型，不影响本次 PRD 评审”。
