# 强制澄清边界

以下情况必须先提问，得到用户回答后才能继续。提问前不得写 PRD、调用原型工具或用业务假设绕过。

## 1. 名词含义不确定

包括但不限于：

- 业务名词、缩写、页面名、单据名或状态名无法唯一对应知识库；
- 同名功能存在两个以上语境；
- 用户使用的词可能是行业术语、产品术语或内部简称，但无法判断其含义。

## 2. 业务逻辑不确定

包括但不限于：

- 触发条件和处理结果不明确；
- 状态流转有多种合理解释；
- 对库存、金额、订单、数据归属或权限的影响不明确；
- 异常、撤销、重试、重复提交或作废规则不明确。

## 3. 交互样式不确定

包括但不限于：

- 入口位置或导航归属不明确；
- 页面、弹窗、抽屉、底部弹层等形态不明确；
- 返回方式、点击/长按/左滑等手势不明确；
- 默认、空态、加载、错误、禁用、成功或失败反馈不明确。

## 提问和恢复规则

1. 只提会阻塞当前决策的最小问题。
2. 问题应包含：当前不确定点、两种主要理解、会影响的业务结果。
3. 等待用户回答，不继续生成半成品 PRD。
4. 用户回答后，将答案作为当前需求最高优先级依据，回到原流程继续执行。
5. 将已确认的名词、规则或交互结论写入 PRD；如果具有长期复用价值，同步更新知识库。

普通资料缺口如果不影响名词、业务逻辑或交互样式，可以标注为业务假设或待确认项继续执行。
