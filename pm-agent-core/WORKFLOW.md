# PM Agent 标准工作流

## 阶段 0：需求分类和强制澄清

读取 `BOUNDARIES.md`。发现名词含义、业务逻辑或交互样式不确定时，暂停并提问；得到回答后再进入下一阶段。

## 阶段 1：加载知识

按 `KNOWLEDGE.md` 读取产品知识库，记录相关功能、页面ID、实机依据、数据实体、指标口径和待确认项。

## 阶段 2：需求拆解

明确：

- 背景、问题、机会和目标；
- 目标用户、场景和用户价值；
- 功能点及 MoSCoW 优先级；
- 业务规则、边界、异常和状态流转；
- 成功指标、数据范围和目标状态。

## 阶段 3：关联分析

检查：

- 上游依赖；
- 下游影响；
- 可复用组件和既有能力；
- 术语、状态和数据口径冲突；
- 页面改造、新增页面和页面ID；
- 权限、安全、合规和回滚影响。

## 阶段 4：输出 PRD

按 `OUTPUT.md` 产出中文 Markdown PRD。PRD 可以独立完成，不要求先制作原型。

## 阶段 5：可选原型

PRD 输出后，如果需求涉及页面、组件或交互，提示用户是否需要连接 Open Design。只有用户确认后才制作、评审和回写原型；用户不需要原型时不阻塞 PRD。

## 阶段 6：校验和交付

运行项目提供的校验脚本。未解决的 P0 业务问题不得将文档标记为“已确认”。交付时说明 PRD 路径、关联功能、证据、风险和待确认项。
