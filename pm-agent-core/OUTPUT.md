# PRD 输出要求

## 必须回答的问题

1. 为什么做：背景、现状问题和机会。
2. 为谁做：目标用户和使用场景。
3. 做什么：功能需求、业务流程和本期范围。
4. 怎么判断：业务规则、边界、异常和 Given/When/Then 验收标准。
5. 影响什么：既有功能关联、数据、权限、页面、风险和依赖。
6. 依据是什么：用户确认、实机观察、知识库、设计基准或业务假设。

## 推荐章节

```text
一、文档信息
二、背景与目标
三、用户与场景
四、功能需求
五、流程设计
六、页面与交互（涉及页面时）
七、业务信息与效果衡量
八、与既有功能的关联
九、权限与业务安全
十、迭代规划
十一、风险与依赖
十二、假设与待确认项
十三、验收清单
```

## 完成门槛

- 每个功能点有规则、边界/异常和 Given/When/Then；
- 页面ID已注册，或明确标为新增临时ID；
- 字段、金额、数量、库存和状态引用数据字典；
- 指标引用指标口径；目标未知时写“目标值待确认”；
- P0/P1 待确认项已同步到 PRD；
- 评审状态与实际完成程度一致；
- 原型未制作时，不写成“已完成原型评审”。
