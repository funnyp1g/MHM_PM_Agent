# APP 实机页面观察记录

> 观察日期：2026-08-07。设备：iPhone 16 Pro。入口：macOS「iPhone镜像」。当前店铺：多店测试。当前账号：老板。App版本：v1.43.6（构建标识：2026072300）。
> 本文记录当前设备、当前账号和当前版本下实际看到的页面，不替代 `design-system.md` 的目标设计基准。

## Agent 使用规则

1. 先读取 `design-system.md` 了解目标视觉与交互规范。
2. 再读取 `pages.md` 了解页面ID、页面关系和已有页面快照。
3. 涉及当前页面真实结构时，读取本文；本文中的截图和实机观察优先用于判断当前版本实际展示。
4. 如果本文与设计基准或业务文档冲突，必须标注为“设计记录与实机观察不一致”，不能直接臆断原因。优先检查版本、店铺类型、岗位权限和数据状态。

## 已确认业务规则

- 本次实机观察使用老板账号；老板账号开放全部功能。
- 本次知识整理以老板账号为目标，不展开店长/店员权限划分。
- 补货提交生成采购请求，不直接增加库存；真正到货后仍需通过进货入库改变库存。
- 实机「采购进货→补货单」Tab 与上述 SKU 补货采购请求是不同功能：前者是当前 App 的平台货品/其他货品处理购物车，后者是独立的补货采购请求模型。
- 销售收款、进货提交、补货提交、作废等业务流程暂不作为已确认规则；本次实机操作以页面和提交前状态观察为主。

## 页面:home

- 顶部状态区显示时间、网络、电量和当前店铺头像。
- 店铺栏显示「多店测试」及店铺切换图标，右侧有日历入口。
- 主导航为「首页 / 数据 / 营销」，当前页使用红色高亮和下划线。
- 主体从上到下为：通知横幅、日期操作栏、卖货卡片、进货卡片、会员卡片、货品卡片。
- 通知横幅当前出现过「卖货猫功能更新」「去查看」和关闭图标，属于动态内容，不能写死为固定文案。
- 日期栏格式为 `2026.08.07 [星期五]`，右侧有编辑、展示、说明入口。
- 卖货卡片展示订单、销售件数、营业额、客单价、连带率、客单数、单笔最多、单笔最高；右上角为「开单」「详情 >」。
- 进货卡片展示款数、件数、合计；当前实机只显示「进货」和「详情 >」。
- 会员卡片展示总数、新增、复购；右上角为「添客」「详情 >」。
- 货品卡片展示总数、增加、减少；右上角为「建款」「详情 >」。
- 右下角固定红色圆形「更多功能」按钮，遮盖在内容滚动层之上。
- 当前数据大多为 0，会员总数为 9；零数据并不会隐藏卡片。

## 页面:data

- 顶部仍保留店铺栏和三 Tab 主导航。
- Tab 下方为五个横向功能入口：销售&利润、货品分析、会员分析、店员业绩、营业汇总。
- 日期栏包含日期下拉、环比/同比切换和导出入口；实机当前「环比」为选中态。
- 主体第一个白色区域标题为「销售趋势」，零数据时图表区域为空白但容器仍保留。
- 下方为销售对比表，表头包含「昨日 / 今日 / 环比」，当前可见指标包括销售数、销售额、销售笔数、抹零。
- 环比结果在零数据状态下以红色 `0%` 展示。
- 右下角仍固定显示「更多功能」悬浮按钮。

## 页面:sales-create

- 顶部为返回箭头、居中标题「开单」、右侧「挂单」。
- 页面打开时，如果存在未完成销售单，先弹出「温馨提示」：有销售单未完成，是否继续完成；按钮为「重新开单」和「继续完成」。
- 继续后页面依次展示：会员信息、价格类型、整单打折、添加货品方式、商品明细、底部固定结算栏。
- 会员栏显示会员姓名/等级、积分、余额，右侧为进入选择的箭头。
- 价格类型当前展示「销售价」，整单打折当前展示「不打折」。
- 添加货品区域提供「手机扫码」「选择货品」「扫码枪」三个入口；扫码枪旁可显示连接状态。
- 商品行使用白色卡片，包含货品图、货品名、款号、规格、销售价、实收价；右侧提供「赠品」「欠货」状态按钮和删除图标，实收价旁有编辑图标。
- 底部固定结算栏展示售出件数、退货件数、应收金额、优惠金额、「查看明细」和红色「去收银」按钮。
- 当前实机存在商品数据，因此本次观察未覆盖无商品空态；新增 PRD 时仍需沿用底部固定结算栏结构。

## 页面:purchase-entry

- 从首页进货卡片点击「进货」后，弹出标题为「选择入库方式」的白色圆角底部弹层，右上角有关闭图标。
- 弹层包含五个纵向入口：
  - 一键入库：供应商订单数据同源，一键入库。
  - 扫码入库：供应商订单数据同源，扫运单、商品入库。
  - 某花小票：带「内部」标记。
  - AI智能入库：全渠道、上传小票图片、AI智能入库。
  - 手动点货入库：常规入库方式。
- 每个入口由左侧彩色图标、标题、说明文案和右侧箭头组成，入口之间使用浅灰分割线。

## 页面:goods-list

- 顶部为返回箭头、Tab「货品 / 盘点」，当前「货品」红色高亮。
- Tab 下方有换季仓、 新增、日志、设置等快捷入口。

## 设计基准与实机差异

| 项目 | 设计/知识库记录 | 实机观察 | Agent 处理方式 |
|---|---|---|---|
| 首页进货快捷入口 | 记录为「进货」「补货」两个按钮 | 当前只看到「进货」 | 以当前权限/版本为条件，不默认补货入口一定可见 |
| 补货入口 | `replenish-select` 属于后续 SKU 补货采购请求功能 | 本次账号画面未出现 | 后续功能范围，本项目不要求补充当前入口 |
| 数据页趋势图 | 设计文档描述 7 日折线图 | 零数据时图表容器为空白 | 保留图表容器和加载/空数据状态，不把空白误判为缺少组件 |
| 开单页初始状态 | 设计快照以商品行作为示例 | 当前先出现未完成销售单提示 | 将未完成单提示作为页面进入前置状态 |
| 账号权限 | 当前知识整理以老板账号为目标 | 本次实机为老板账号 | 本项目不展开店长/店员权限划分 |
| 建款入口文案 | 设计文档未展开建款弹层 | 标题为「选择入库方式」，内容为批量建款/新建单款 | 按实际内容理解，记录文案冲突，不复用错误标题 |
| 采购进货补货单 Tab | 08-replenishment 定义为补货采购请求 | 实机展示平台货品/其他货品购物车及处理状态 | 已确认是两个不同功能；PRD 不得复用页面ID、字段或状态机 |
| 新建盘点计划 | 设计文档未描述打开页面是否创建计划 | 打开后自动出现进行中计划 00002 | 盘点页面 PRD 必须确认进入页面是否即创建业务单据 |
