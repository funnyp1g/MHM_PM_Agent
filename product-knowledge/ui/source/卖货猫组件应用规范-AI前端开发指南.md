# 卖货猫组件应用规范

> 面向 AI 快速前端开发的实现指南
>
> 设计来源：[卖货猫组件应用规范 – Figma](https://www.figma.com/design/T1UK3TvwdSr628Jf2F0tng/%E5%8D%96%E8%B4%A7%E7%8C%AB%E7%BB%84%E4%BB%B6%E5%BA%94%E7%94%A8%E8%A7%84%E8%8C%83)

## 1. 使用说明

本规范用于生成、改造和评审卖货猫后台及移动端页面。AI 生成前端代码时，优先遵循本文件中的设计令牌、组件语义和交互约束；如果业务需求与规范冲突，应优先复用已有组件，再通过参数扩展，而不是重新创造一套视觉样式。

### 1.1 实现优先级

1. 先复用设计令牌：颜色、圆角、字号、间距和控件高度。
2. 再复用组件：按钮、表单、弹窗、标签、通知、时间选择、表格等。
3. 再处理业务差异：文案、字段、状态、权限和数据结构。
4. 最后处理装饰：图标、插画、空状态和品牌素材。

### 1.2 默认技术约束

- 使用语义化 HTML、可访问的表单控件和键盘可操作的交互。
- 组件应支持受控状态、禁用状态、加载状态和错误状态。
- 优先使用 CSS 变量承载令牌，避免在业务组件中散落硬编码颜色。
- 桌面端优先适配后台管理场景；移动端遵循规范中的顶部导航、Tab 和操作栏示例。
- 规范页没有单独定义的字体、阴影和动效，不要擅自引入复杂视觉效果；优先继承项目现有基础样式。

## 2. 设计基调

- **品牌感**：以高饱和红色/珊瑚红为主要操作色，搭配浅粉背景和白色卡片。
- **信息层级**：通过主色、深色文本、次级文本、提示文本和浅灰背景区分信息优先级。
- **形状语言**：按钮和状态控件以圆角胶囊形为主；内容卡片保持轻量、干净、低阴影。
- **布局语言**：页面使用浅灰蓝背景，大块内容放入白色或近白色卡片，区块之间使用细分隔线。
- **密度**：后台表单和表格可保持中高信息密度，但每个字段仍需具备清晰标签、状态和错误反馈。

## 3. 设计令牌

### 3.1 颜色

以下值按 Figma 色板中的标注整理。实现时应统一通过 CSS 变量或主题对象使用。

#### 品牌色

| Token | 值 | 用途 |
|---|---|---|
| `--brand-0` | `#FFF7F8` | 品牌色最浅背景、浅色提示区域 |
| `--brand-1` | `#FFEBED` | 浅色按钮、弱强调背景 |
| `--brand-2` | `#FFD6DC` | 选中态背景、弱边框或分割区域 |
| `--brand-3` | `#FFADB8` | 次级强调、浅色状态 |
| `--brand-4` | `#FF8595` | 中等强调、悬停或辅助状态 |
| `--brand-5` | `#FF5C71` | 强调色、重要操作的浅阶状态 |
| `--brand-primary` | `#920990` | Figma 标注的主题色/主品牌色；使用前应与项目实际变量再次核对 |
| `--brand-7` | `#EB2F48` | 强操作、主按钮和高优先级状态 |
| `--brand-8` | `#D62B42` | 主色深阶、按下态或深色强调 |
| `--brand-9` | `#C2273B` | 主色最深阶、深色文本或极强强调 |

#### 中性色

| `--color-special-pink` | `#FF1DBA` | 特价、营销或强促销标签 |

### 3.2 颜色使用规则

- 主按钮使用强品牌色；同一操作区最多保留一个主按钮。
- 次级按钮使用浅品牌背景，普通按钮使用浅灰背景或描边，幽灵按钮使用透明背景。
- 错误色只表示错误或危险，不用于普通装饰。
- 状态色应同时配合文字或图标，不依赖颜色单独传达含义。
- 页面背景使用 `--color-bg`，内容卡片使用 `--color-white` 或 `--color-card`。
- 重要数字可以使用品牌色或功能色突出，但不要让整段正文变成高饱和色。

## 4. 图标规范

### 4.1 基础网格

- 以 `24 × 24px` 作为图标绘制的统一网格尺寸。
- 图标内部需要以网格为基准对齐关键路径和视觉重心。
- 图标在不同尺寸下应保持线宽、留白和视觉重量的一致性。

### 4.2 推荐尺寸阶梯

Figma 规范建议使用两级尺寸阶梯：

- 第一阶：`4px`、`8px`、`12px`、`16px`、`20px`、`24px`。
- 第二阶：`32px`、`40px`、`48px`、`56px`、`64px`、`72px`、`80px`。

当业务需要非标准尺寸时，优先从相邻尺寸阶梯选择，不要随意使用 `18px`、`22px`、`26px` 等中间值。

### 4.3 图标使用

- 默认图标尺寸为 `16px` 或 `24px`，由控件高度决定。
- 图标与文字同时出现时，图标应与文字垂直居中，并保持固定间距。
- 使用图标按钮时必须提供 `aria-label` 或可见文本。
- 同一个页面内不要混用不同风格的线性图标、面性图标和品牌图标。
- 图标不能替代必要文字，例如删除、保存、确认等关键操作应保留文字或辅助提示。

## 5. 排版和布局

### 5.1 页面结构

推荐采用以下页面层级：

```text
页面背景
└── 页面容器
    ├── 页面标题区
    ├── 筛选/搜索区
    ├── 内容卡片或表格
    └── 分页、提交或辅助操作区
```

- 页面主背景使用浅灰蓝色，内容区域使用白色或近白色卡片。
- 大区块之间使用标题、细分隔线和稳定的垂直间距。
- 区块标题分为“一级标题”“二级标题”“带说明标题”三类。
- 带说明标题用于需要补充解释或操作提示的场景，说明文字使用次级文本色。
- 不要为了填充空间加入无意义的卡片、阴影或渐变。

### 5.2 响应式原则

- 桌面端优先使用横向表单、双列字段和宽表格。
- 窄屏时将双列字段堆叠为单列；保持字段标签与错误提示完整可见。
- 表格在移动端优先采用横向滚动、关键列固定或卡片化降级，不要压缩到不可读。
- 顶部导航在移动端使用返回按钮、居中标题和右侧操作图标。
- Tab 导航同时承担页面切换和当前操作提示，选中项使用品牌色和底部指示线。

## 6. 通用组件

### 6.1 按钮

规范中的按钮按视觉重量从重到轻排列：

1. **主要按钮**：高饱和品牌色背景，白色文字，用于页面主任务。
2. **次级按钮**：浅品牌背景，品牌色文字，用于同级辅助任务。
3. **普通按钮**：浅灰背景或中性色，用于低优先级操作。
4. **幽灵按钮**：透明或描边，仅在背景干净、层级明确时使用。

按钮需要覆盖：

- 默认、悬停、按下、禁用、加载和危险状态。
- 纯文字按钮、图标按钮、图标 + 文字按钮。
- `24px` 和 `28px` 等紧凑尺寸变体，具体尺寸随页面密度选择。
- 文字不宜过长；操作文案优先使用“查询”“保存”“确认”“取消”“重置”等明确动词。

```tsx
<Button variant="primary" size="medium" loading={isSaving}>
  保存
</Button>
```

### 6.2 标签和状态标签

- 普通状态标签使用中性色或浅品牌背景。
- 成功、警告、错误标签分别使用对应状态色，并配合文字说明。
- `ICON 标签`用于需要强化状态识别的场景，例如已启用、已停用、促销或特殊业务状态。
- 标签文字尽量短，避免在标签内放置完整句子。

### 6.3 通知和轻提示

规范区分“常规通知”和“可关闭通知栏”：

- **常规通知**：用于一般通知、提示和状态说明；不抢夺页面主焦点。
- **可关闭通知栏**：用于操作反馈和功能提示；右侧提供关闭或“我知道了”。
- **Toast 轻提示**：用于短暂反馈，如保存成功、复制完成、操作失败；避免承载复杂说明。
- Toast 的内容应简短、可读，并在必要时提供明确的下一步动作。

### 6.4 标题

- 一级标题：用于页面或大区块标题，视觉权重最高。
- 二级标题：用于常规内容分组。
- 标题 + 说明：标题后跟简短解释，说明使用次级文本色。
- 标题旁的帮助图标只用于补充信息，不应替代标题本身。

### 6.5 Tab 和移动端导航

- Tab 选中态使用品牌色文字和底部短指示线。
- 未选中项使用次级文本色，保持足够的点击区域。
- 移动端顶部导航包含返回按钮、居中标题和可选的右侧操作。
- 如果右侧有多个图标操作，必须提供明确的无障碍标签和点击反馈。

### 6.6 查询汇总条

规范中展示了“合计金额 + 入库件数 + 查询/重置”的查询汇总模式：

- 金额等关键数字使用品牌色或业务强调色。
- 次要统计信息使用次级文本色。
- “查询”作为主操作，“重置”作为弱操作。
- 支持全选时使用复选框，并保证复选框和文字的点击区域一致。

### 6.7 时间选择器

规范包含“选择时间”和“选择时间维度”两类模式：

- 时间维度可使用“按天”等下拉选择。
- 支持前一天、后一天和当前日期显示。
- 当前日期或选中日期使用品牌色强调。
- 日期格式统一，示例格式为 `2025.12.12`；业务实现应按项目约定统一格式。

## 7. 表单和表格

### 7.1 表单字段

表单规范覆盖搜索框、选择器、开关、级联选择、输入框、表格内编辑和图片选择等场景。

- 每个字段必须有明确标签；不要只依赖 placeholder 作为标签。
- 必填项使用统一标记，错误信息放在字段下方并使用错误色。
- 输入框、选择器、级联选择器保持同一控件高度和对齐方式。
- 字段较多时使用双列布局；强相关字段放在同一行。
- 数字、金额、库存、价格等字段需要限制输入类型、精度和合法范围。
- 开关用于即时启停或二元状态，不要用开关表示需要提交后才生效的复杂流程。
- 图片选择区域需要显示缩略图、删除入口、上传状态和数量限制。

### 7.2 搜索与筛选

- 搜索区优先放置高频筛选条件，低频条件放入更多筛选或折叠区域。
- 查询和重置按钮保持明确主次关系。
- 搜索条件变更后，结果区应有加载状态；禁止在请求期间重复提交。
- 空结果需要明确显示“无结果”并提供清空条件或重置入口。

### 7.3 表格

- 表头、单元格和操作列保持统一对齐规则。
- 金额、数量、日期等数据使用稳定的数字和日期格式。
- 行内操作优先使用短文字按钮或图标 + Tooltip。
- 批量操作需要配合行选择和全选状态。
- 长文本使用省略号时，必须提供 Tooltip 或详情查看方式。
- 表格底部提供分页或加载更多；分页与筛选条件联动时应重置到合理页码。

## 8. 弹窗、底部弹窗和对话框

### 8.1 底部弹窗

规范示例包括：默认底部弹窗、带筛选/搜索的弹窗、仅操作弹窗。

- 用于需要在当前页面上下文中完成选择、筛选或快速操作的任务。
- 底部弹窗内部应有清晰标题、内容区和底部操作区。
- 内容较长时允许滚动，但操作区保持可见或固定在底部。
- 选择型弹窗需要明确当前选择、确认按钮和取消/关闭方式。
- 仅操作弹窗适合简单的二选一或快速确认，不要塞入复杂表单。

### 8.2 对话框

规范示例包括二次确认、默认说明、带解释内容、编辑型对话框。

- **二次确认**：用于删除、下架、提交等不可逆或高风险操作。
- **默认说明**：用于简短的结果确认或信息提示。
- **解释内容**：用于需要补充规则、影响范围或风险说明的场景。
- **编辑型对话框**：用于少量字段的快速编辑；字段较多时改用独立页面或底部弹窗。
- 主操作放在右侧或操作区末尾，取消为弱操作。
- 危险操作使用危险色，并在文案中明确后果。
- 点击遮罩关闭只适用于非关键流程；未保存内容的编辑弹窗应阻止误关闭或给出确认。

## 9. 交互状态

每个可交互组件至少设计以下状态：

| 状态 | 要求 |
|---|---|
| 默认 | 展示正常可操作状态 |
| 悬停 | 通过颜色、边框或轻微背景变化反馈 |
| 按下 | 明确表示操作已触发 |
| 聚焦 | 键盘操作时必须可见，不能只依赖鼠标样式 |
| 禁用 | 降低对比度并阻止操作，同时保留必要说明 |
| 加载 | 防止重复提交，并保留当前操作语义 |
| 成功 | 使用成功色、成功提示或状态标签 |
| 错误 | 使用错误色、字段级提示和可恢复操作 |
| 空状态 | 说明当前没有数据，并提供下一步操作 |

## 10. AI 生成前端时的组件映射

| 业务意图 | 优先使用 |
|---|---|
| 页面主任务 | 主要按钮 |
| 次要动作 | 次级按钮或普通按钮 |
| 高风险操作 | 危险按钮 + 二次确认对话框 |
| 筛选条件 | 输入框、选择器、级联选择器、日期选择器 |
| 二元状态 | 开关 |
| 状态展示 | 状态标签、ICON 标签、通知栏 |
| 少量快速编辑 | 编辑型对话框 |
| 选择列表 | 底部弹窗或选择器 |
| 长列表数据 | 表格 + 分页 |
| 短暂反馈 | Toast 轻提示 |
| 页面分区 | 一级/二级标题 + 分隔线 |
| 移动端模块切换 | Tab |

## 11. AI 输出检查清单

生成代码前后，逐项检查：

- [ ] 是否复用了颜色令牌，而不是新造品牌红、灰色或状态色？
- [ ] 是否只使用规范中的按钮层级，并且一个区域只有一个主操作？
- [ ] 是否覆盖加载、禁用、错误、空状态和成功反馈？
- [ ] 表单字段是否有真实 label、校验规则和错误提示？
- [ ] 弹窗是否明确标题、内容、取消和确认操作？
- [ ] 危险操作是否有二次确认，且文案说明后果？
- [ ] 图标是否使用 `24px` 网格和推荐尺寸阶梯？
- [ ] 移动端是否处理了顶部导航、Tab、双列字段和宽表格？
- [ ] 是否保留键盘操作、焦点态和 `aria-label`？
- [ ] 是否避免使用未在规范中定义的渐变、重阴影、玻璃拟态或复杂动画？

## 12. 推荐的 AI 实现提示词

可将以下提示词作为前端生成任务的固定前缀：

