# 设计系统规范

> 本文是卖货猫页面、组件和交互规范的权威摘要。PRD「页面与交互」章节、页面快照和前端实现必须遵循本文，不自行发明样式。
>
> 业务页面基准来源：`ui/source/APP页面设计规范及功能位置参考.md`（多店版，2026-08-07）。
>
> 组件和 AI 前端实现来源：`ui/source/卖货猫组件应用规范-AI前端开发指南.md`（Figma 组件应用规范，2026-08-11 纳入知识库）。

## 使用原则

适用于卖货猫后台及移动端页面的生成、改造和评审。业务需求与规范冲突时，按以下优先级处理：

1. 先复用设计令牌：颜色、圆角、字号、间距、控件高度和状态色。
2. 再复用已有组件：按钮、表单、弹窗、标签、通知、时间选择器、表格等。
3. 再处理业务差异：文案、字段、状态、权限和数据结构。
4. 最后处理装饰：图标、插画、空状态和品牌素材。

不得因为单个页面的视觉偏好重新创造一套颜色、圆角、阴影或动效。

### 规范冲突处理

- **现有 App 页面基线优先**：首页、数据、营销、开单等已注册页面继续使用珊瑚红主色和多店版页面结构。
- **Figma 组件令牌作为补充**：组件实现可使用 AI 指南中的令牌名称和状态语义；若 Figma 标注值与已绑定的组件变量或实机页面不一致，以组件实际绑定变量、已确认实机结果为准。
- **新增页面先复用后扩展**：新增页面应复用 `pages.md` 已登记的页面范式和本文组件；确需新样式时，在 PRD 中记录原因和影响，不直接覆盖既有基线。

## 产品架构

- **顶部主导航（三大 Tab）**：首页（左）/ 数据（中）/ 营销（右），横向切换。
- **全局悬浮入口**：右下角圆形红色「更多功能」悬浮按钮，贯穿首页/数据/营销三页，点击进入全功能列表。
- **后台页面结构**：页面背景 → 页面容器 → 页面标题区 → 筛选/搜索区 → 内容卡片或表格 → 分页、提交或辅助操作区。
- **移动端页面结构**：顶部返回按钮、居中标题、右侧操作图标；页面内使用 Tab 或底部固定操作区承载当前任务。

## 设计基调

- **品牌感**：以高饱和红色/珊瑚红为主要操作色，搭配浅色背景和白色卡片。
- **信息层级**：通过主色、主文字、次级文字、提示文字和背景色区分优先级。
- **形状语言**：按钮和状态控件以圆角胶囊形为主；内容卡片保持轻量、干净、低阴影。
- **布局语言**：页面使用浅灰或浅灰蓝背景，大块内容放入白色/近白色卡片，区块之间使用标题和细分隔线组织。
- **信息密度**：后台表单和表格可保持中高密度，但每个字段仍需有清晰标签、状态和错误反馈。
- **装饰克制**：未在规范中定义的渐变、重阴影、玻璃拟态和复杂动画不得默认引入。

#### 颜色使用规则

- 主按钮使用强品牌色；同一操作区最多保留一个主按钮。
- 次级按钮使用浅品牌背景，普通按钮使用浅灰背景或描边，幽灵按钮使用透明背景。
- 错误色只表示错误或危险，不用于普通装饰。
- 状态色必须同时配合文字或图标，不依赖颜色单独传达含义。
- 页面背景使用页面基线背景色或 `--color-bg`，内容卡片使用白色或 `--color-card`。
- 重要数字可以使用品牌色或功能色突出，但不要让整段正文变成高饱和色。

## 图标规范

- 以 `24 × 24px` 作为图标绘制的统一网格尺寸。
- 推荐尺寸阶梯为 `4px`、`8px`、`12px`、`16px`、`20px`、`24px`，以及 `32px`、`40px`、`48px`、`56px`、`64px`、`72px`、`80px`。
- 默认图标尺寸为 `16px` 或 `24px`，由控件高度和信息密度决定。
- 图标与文字同时出现时垂直居中，并保持固定间距。
- 同一页面不要混用线性、面性和品牌图标风格；当前 App 页面优先使用面性图标和圆形/圆角方形底。
- 图标按钮必须提供 `aria-label` 或可见文本；删除、保存、确认等关键操作不能只依赖图标表达。

## 字体、排版与布局

### 字体层级

- 字体使用系统默认无衬线字体（苹方/思源黑体）。
- 页面大标题：`18–20px`，粗体。
- 卡片标题：`16–17px`，粗体，可搭配彩色图标。
- 数据数字：`22–28px`，常规字重，醒目突出。
- 指标标签：`12–13px`，使用次级或弱文字色。
- 列表正文：`14–15px`。

### 页面与间距

- 页面主背景使用浅灰白或浅灰蓝色，内容区域使用白色或近白色卡片。
- 顶部导航栏高度约 `180px`，包含状态栏、店铺信息栏和 Tab 栏。
- 卡片圆角为 `12–16px`，卡片内边距左右 `16px`、上下 `20px`。
- 页面左右边距为 `12–16px`，模块间距为 `12–16px`。
- 数据卡片内的卖货、进货、会员数据优先采用三列等分布局。
- 大区块通过标题、说明文字、细分隔线和稳定的垂直间距组织，不使用无意义的卡片填充空间。

### 响应式原则

- 桌面端优先使用横向表单、双列字段和宽表格。
- 窄屏将双列字段堆叠为单列，保持字段标签与错误提示完整可见。
- 移动端宽表格优先采用横向滚动、关键列固定或卡片化降级，不压缩到不可读。
- 移动端顶部使用返回按钮、居中标题和右侧操作图标；Tab 选中项使用品牌色和底部指示线。
- 固定底部操作栏需要预留安全区域，不能遮挡表单、列表或系统手势区域。

## 通用组件

### 按钮

按视觉重量从重到轻分为：

1. **主要按钮**：高饱和品牌色背景、白色文字，用于页面主任务。
2. **次级按钮**：浅品牌背景、品牌色文字，用于同级辅助任务。
3. **普通按钮**：浅灰背景或中性色，用于低优先级操作。
4. **幽灵按钮**：透明或描边，仅在背景干净且层级明确时使用。

按钮需要覆盖默认、悬停、按下、聚焦、禁用、加载和危险状态，并支持纯文字、图标、图标 + 文字三种内容形式。紧凑场景可使用 `24px`、`28px` 等尺寸变体，但同一操作区应保持高度一致。

### 标签、状态标签与标题

- 标签/徽章使用圆角矩形、浅色背景和彩色文字，例如「开单」「赠品」「欠货」。
- 状态标签需要同时表达状态文字，正负变化可用绿（↑）/红标注，但不能只用颜色表达。
- 一级标题用于页面主标题，二级标题用于卡片或区块标题，带说明标题用于补充规则或操作提示。
- 标题、说明和操作按钮应保持稳定的水平对齐关系；不要用颜色替代标题层级。

### 通知和轻提示

- 通知栏用于页面级重要提示、规则说明或风险告知，应可被用户识别和阅读。
- Toast 用于短暂、非阻塞的结果反馈，成功、警告和错误需要有明确文案。
- 错误反馈优先靠近产生错误的字段或操作；不可只显示无上下文的全局错误提示。

### Tab、移动端导航与查询汇总条

- 顶部主 Tab 固定为首页/数据/营销；移动端 Tab 同时承担页面切换和当前操作提示。
- Tab 选中项使用品牌色和底部指示线，未选中项使用次级文字色。
- 查询汇总条用于展示当前筛选结果、数量、金额或时间范围，并提供清空/重置入口。
- 查询汇总条中的数字格式应稳定，金额、数量和日期不得混用展示规则。

### 时间选择器

- 数据页统一在顶部提供日期选择器，支持环比/同比切换。
- 选择日期后应明确当前范围，并同步刷新关联数据。
- 日期范围无效、数据为空或加载失败时，需要显示可理解的反馈和恢复操作。

## 表单与表格

### 表单字段

- 每个字段必须有真实 `label`、明确的输入类型、占位提示、校验规则和错误提示。
- 必填项、格式要求、长度限制和权限限制应在字段附近说明。
- 字段错误应保留用户输入，明确指出修复方式；提交期间禁用重复提交并保留当前操作语义。
- 双列字段仅在桌面端空间足够时使用，移动端堆叠为单列。

### 搜索与筛选

- 搜索框、选择器、级联选择器和日期选择器应根据业务意图选择，不用一个组件替代所有筛选场景。
- 搜索或筛选请求期间显示加载状态并禁止重复提交。
- 空结果需要明确显示「无结果」，并提供清空条件或重置入口。

### 表格

- 表头、单元格和操作列保持统一对齐；金额、数量、日期使用稳定格式。
- 行内操作优先使用短文字按钮或图标 + Tooltip。
- 批量操作必须配合行选择、全选和部分选中状态。
- 长文本使用省略号时，必须提供 Tooltip 或详情查看方式。
- 表格底部提供分页或加载更多；筛选条件变化时重置到合理页码。

## 弹窗、底部弹窗与对话框

### 底部弹窗

- 用于在当前页面上下文中完成选择、筛选或快速操作。
- 内部应有清晰标题、内容区和底部操作区；内容较长时允许滚动，但操作区保持可见或固定在底部。
- 选择型弹窗需要明确当前选择、确认按钮和取消/关闭方式。
- 仅操作弹窗适合简单的二选一或快速确认，不塞入复杂表单。

### 对话框

- 删除、下架、提交等不可逆或高风险操作必须使用二次确认，并在文案中明确后果。
- 默认说明对话框用于简短结果确认；解释型对话框用于规则、影响范围或风险说明。
- 编辑型对话框仅用于少量字段的快速编辑，字段较多时改用独立页面或底部弹窗。
- 主操作放在右侧或操作区末尾，取消为弱操作；危险操作使用危险色。
- 点击遮罩关闭只适用于非关键流程；未保存编辑内容关闭前必须阻止误关闭或给出确认。

## 交互状态与反馈

每个可交互组件至少设计以下状态：

| 状态 | 要求 |
|---|---|
| 默认 | 展示正常可操作状态 |
| 悬停 | 通过颜色、边框或轻微背景变化反馈 |
| 按下 | 明确表示操作已触发 |
| 聚焦 | 键盘操作时必须可见，不能只依赖鼠标样式 |
| 禁用 | 降低对比度并阻止操作，同时保留必要说明 |
| 加载 | 防止重复提交，并保留当前操作语义 |
| 成功 | 使用成功色、成功提示或状态标签 |
| 错误 | 使用错误色、字段级提示和可恢复操作 |
| 空状态 | 说明当前没有数据，并提供下一步操作 |

## 既有页面交互模式

| 交互模式 | 说明 |
|----------|------|
| 顶部 Tab 切换 | 首页/数据/营销三页通过顶部 Tab 横向切换 |
| 卡片详情跳转 | 数据卡片右上角使用「详情 >」进入细分页面 |
| 快捷操作按钮 | 卡片右上角使用红色胶囊按钮直达开单、进货、添客、建款 |
| 右下角悬浮按钮 | 「更多功能」常驻悬浮，进入全功能列表 |
| 日期选择器 | 数据页统一顶部日期选择，支持环比/同比切换 |
| 列表左滑删除 | 开单页商品行支持删除操作，并提供明确反馈 |
| 状态标签切换 | 商品行支持赠品/欠货等状态切换 |
| 底部固定结算栏 | 开单页底部固定显示合计和「去收银」主按钮 |

## AI 生成前端时的组件映射

| 业务意图 | 优先使用 |
|---|---|
| 页面主任务 | 主要按钮 |
| 次要动作 | 次级按钮或普通按钮 |
| 高风险操作 | 危险按钮 + 二次确认对话框 |
| 筛选条件 | 输入框、选择器、级联选择器、日期选择器 |
| 二元状态 | 开关 |
| 状态展示 | 状态标签、Icon 标签、通知栏 |
| 少量快速编辑 | 编辑型对话框 |
| 选择列表 | 底部弹窗或选择器 |
| 长列表数据 | 表格 + 分页 |
| 短暂反馈 | Toast 轻提示 |
| 页面分区 | 一级/二级标题 + 分隔线 |
| 移动端模块切换 | Tab |

## AI 输出检查清单

生成代码前后逐项检查：

- [ ] 复用了颜色令牌，没有新造品牌红、灰色或状态色。
- [ ] 只使用规范中的按钮层级，同一操作区只有一个主操作。
- [ ] 覆盖加载、禁用、错误、空状态和成功反馈。
- [ ] 表单字段有真实 `label`、校验规则和错误提示。

## 页面设计原则

1. **数据仪表盘化**：首页/数据页以数据卡片组织，卡片内三列等分网格，右上角「详情 >」进入细分。
2. **直达式快捷操作**：核心动作以红色胶囊按钮直接暴露在卡片右上角。
3. **分类聚合入口**：低频功能集中在「更多功能」页按店铺、硬件设备、供应商、库存管理等分类聚合。
4. **状态可视化**：正负变化用绿（↑）/红标注，标签使用浅色底和彩色字，并配合文字或图标。
5. **业务优先于装饰**：页面首先保证任务完成、状态可理解、异常可恢复，再考虑视觉装饰。
