# 功能模块：补货采购请求

## 基本信息

- **功能模块**：补货采购请求
- **产品阶段**：后续新功能；当前版本实机页面和入口不作为本功能的分析前置条件
- **最后更新**：2026-08-07
- **来源**：《卖货猫app产品使用手册》+ PRD 2026-08-06-replenishment +《APP页面设计规范及功能位置参考.md》（多店版）+ 2026-08-07 老板账号实机观察
- **相关页面**：`replenish-select` 补货选品页（详见 `ui/pages.md`）。注意：它与 `02-purchase` 的 `replenishment-tab` 是不同功能。

## 功能描述

- **一句话概述**：独立于采购进货补货单 Tab 的 SKU 补货采购请求功能；选择货品 SKU 加入补货车，确认后生成采购请求，用于热销款/断码款快速发起补货。
- **解决的用户问题**：店主在缺货/断码场景下快速批量发起补货，缩短「发现缺货 → 发起补货」路径。
- **核心场景**："热销款断码了怎么补货""批量给缺货款下补货单"。

## 能力清单

- **补货入口**：设计记录曾定义为首页进货卡片右上角红色胶囊「补货」快捷按钮；当前老板账号 v1.43.6 实机未显示该按钮，因此该入口不能视为当前版本已确认事实，需在实现/评审时单独确认入口与功能开关。
- **补货选品**：按货品名称/款号/条码搜索，按品类/品牌筛选；支持扫码添加 SKU；SKU 选择器展示当前库存、销售价、进价。
- **补货车**：加入 SKU（重复加入数量累加）、修改数量（1–999）、删除、清空（二次确认）；底部汇总 SKU 种数/总件数/预估金额；当前会话内保留。
- **确认补货**：提交确认弹窗（种数/总件数/预估金额/供应商可选/备注可选），生成「待补货」状态补货单；补货单是采购请求，提交不改变库存。
- **补货单管理**：列表（时间倒序、状态筛选）、详情；状态机 待补货→已补货/已作废；左滑作废（仅待补货）。

## 关键流程

```text
设计入口（待确认） -> 补货选品页（搜索/筛选/扫码选 SKU）
  -> 加入补货车（可继续选品/修改数量）
  -> 确认补货（弹窗确认）-> 生成补货单（待补货）-> 清空补货车
  -> 补货单管理（查看/作废）
```

## 依赖与关联

- **上游依赖**：货品管理（SKU/库存/价格数据源）、权限配置（「进货」权限）、供应商管理（补货单可选关联）。首页快捷入口仅是设计记录，当前版本未实机确认。
- **下游影响**：无破坏性影响；补货单是采购请求，不改变库存、不生成入库单；真正到货后仍需走进货入库，补货单可作为后续入库数据源。
- **关联功能**：首页（进货卡片入口）、货品管理（选品）、进货入库（衔接）、供应商管理（可选关联）、权限配置（权限控制）。

## 数据与规则

- 补货单核心字段：补货单号、创建人、创建时间、状态、供应商（可选）、备注（可选）、货品明细（SKU/款号/颜色尺码/当前库存/补货数量/进价/预估金额）。
- 状态机：待补货 → 已补货（手动标记/入库联动）→ 已作废（仅待补货可作废）。
- 规则：同一 SKU 重复加入数量累加；补货数量 1–999；补货单内库存为提交时快照；提交不改变库存。
- 权限：补货入口与操作受「进货」岗位权限控制。

## 已知边界与限制

- 补货车仅当前会话保留，退出后清空。
- 当前补货单不直接转为进货单/入库单；后续是否实现补货单到入库单的衔接，需另行定义。
- 补货单号格式为 BHR+日期+流水（假设口径，待确认）。该单号和状态不得套用 `replenishment-tab` 的平台货品处理单据。
